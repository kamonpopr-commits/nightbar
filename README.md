# NIGHTBAR — ระบบจัดการร้านบาร์

เว็บแอป Python + SQLite สำหรับเปิดใน Visual Studio Code หน้าเว็บ HTML/CSS สร้างจาก Python ไม่มีบริการภายนอกหรือ CDN ระบบหลักใช้ Python standard library และแนบไลบรารี qrcode 8.2 ใน vendor/ สำหรับสร้าง QR แบบออฟไลน์ ไม่ต้องติดตั้งแพ็กเกจเพิ่มในการเปิดใช้งาน

## เริ่มต้น

สำหรับเครื่องนี้: รัน `.\START.bat` ใน Terminal หรือดับเบิลคลิก `START.bat` แล้วเปิด http://127.0.0.1:8765 ตัวเปิดระบบใช้ Python ที่มีอยู่กับ Codex จึงไม่ติดปัญหา Windows Store alias ของคำสั่ง `python` การตั้งค่า VS Code ชี้ไปที่ Python นี้ด้วย หากย้ายโปรเจกต์ไปเครื่องอื่นให้เลือก interpreter ของเครื่องนั้นและปรับช่อง `python` ใน `.vscode/launch.json`

1. ติดตั้ง Python 3.11 ขึ้นไป และ Visual Studio Code
2. เปิดไฟล์ `Nightbar.code-workspace` ด้วย VS Code และติดตั้งส่วนขยาย Python ตามคำแนะนำ
3. เลือก Python interpreter ที่ติดตั้งไว้
4. เปิด Terminal ของ VS Code แล้วรัน `python app.py` (Windows ใช้ `py app.py` ได้ด้วย)
5. เปิด http://127.0.0.1:8765 และสร้างบัญชีผู้จัดการครั้งแรก ไม่มีรหัสผ่านเริ่มต้น
6. ครั้งต่อไปเข้าสู่ระบบด้วยบัญชีที่สร้าง กด Ctrl+C ใน Terminal เพื่อหยุด

กด F5 เพื่อรันผ่าน Debugger ได้ หลังติดตั้งส่วนขยาย Python Debugger

## ฟังก์ชัน

- Dashboard ยอดขายวันนี้ บิลชำระแล้ว โต๊ะใช้งาน สินค้าใกล้หมด
- โต๊ะ 12 โต๊ะ เปิดบิล เพิ่ม/ลบรายการและตัด/คืนสต็อกทันที
- ชำระเงินสด โอน หรือบัตร บันทึกช่องทางเท่านั้น ไม่มีการเชื่อมธนาคารหรือเครื่องรับบัตร
- ส่วนลดโดยผู้จัดการ ค่าบริการและภาษีตั้งค่าได้ ใบรับเงินพิมพ์ด้วย Ctrl+P
- เพิ่มสินค้า แก้ไขราคา ซ่อนสินค้า ปรับสต็อกพร้อมเหตุผล
- จองโต๊ะ ตรวจความจุและป้องกันจองโต๊ะเดียวกันห่างน้อยกว่า 2 ชั่วโมง
- รายจ่าย รายงานตามช่วงวัน กำไรประมาณการ สินค้าขายดี ส่งออก CSV
- ผู้จัดการ/พนักงาน รหัสผ่าน PBKDF2 CSRF และบันทึกประวัติการทำรายการ
- ดาวน์โหลดสำรอง SQLite จากหน้าตั้งค่า

## SQLite และ DB Browser for SQLite

ฐานข้อมูลถูกสร้างอัตโนมัติที่ `data/nightbar.sqlite3` เปิดด้วยเมนู Open Database ใน DB Browser for SQLite ได้ โดยไม่ต้องติดตั้งไดรเวอร์ฐานข้อมูลเพิ่ม DB Browser เป็นเครื่องมือดู/แก้ไข ไม่ใช่เซิร์ฟเวอร์ฐานข้อมูล

ตารางหลัก: users, tables, products, orders, items, movements, reservations, expenses, audit, settings

ยอดเงินเก็บเป็นจำนวนเต็มหน่วยสตางค์ เช่น 9500 = 95 บาท เพื่อเลี่ยงความคลาดเคลื่อนทศนิยม ราคาและต้นทุนในบิลเก็บเป็น snapshot เมื่อสั่ง การแก้ราคาสินค้าจึงไม่เปลี่ยนบิลเก่า

หยุดแอปก่อนแก้ฐานข้อมูลด้วยมือ เพื่อหลีกเลี่ยงข้อมูลไม่สอดคล้องกัน ห้ามแก้สถานะบิลหรือสต็อกข้ามกระบวนการของแอป สำรองข้อมูลก่อนแก้เสมอ หากต้องการกู้คืน ให้หยุดแอป เก็บสำเนาฐานข้อมูลปัจจุบัน แล้วนำไฟล์สำรองมาแทน `data/nightbar.sqlite3`

## กติกาการคำนวณ

ยอดสินค้า − ส่วนลด = ฐานค่าบริการ จากนั้นคิดภาษีจากฐานรวมค่าบริการ ปัดครึ่งขึ้นที่สตางค์ ค่าเริ่มต้นค่าบริการและภาษีเป็น 0 ให้ตั้งตามร้านของคุณ ใบเสร็จเป็นใบรับเงินทั่วไป ไม่ใช่ระบบออกใบกำกับภาษีเต็มรูป

กำไรประมาณการ = รับชำระ − ภาษีขาย − ต้นทุนรายการ − รายจ่าย ไม่ใช่งบการเงินครบวงจร

สินค้าแต่ละรายการนับเป็นหน่วยขาย ยังไม่มีสูตรตัดวัตถุดิบค็อกเทล/แบ่งขวด ควรลงเมนูให้ตรงหน่วยคงคลัง

## ขอบเขตการใช้งาน

พร้อมทดลองใช้งานบนเครื่องเดียว เซิร์ฟเวอร์เริ่มต้นผูกกับ 127.0.0.1 ไม่เปิดสู่อินเทอร์เน็ต เซสชันเก็บในหน่วยความจำและหมดอายุ 12 ชั่วโมง รีสตาร์ทแล้วต้องเข้าสู่ระบบใหม่

ก่อนเผยแพร่ผ่านอินเทอร์เน็ตควรเพิ่ม HTTPS, เซิร์ฟเวอร์ production, จำกัดการลองรหัสผ่าน/การจองตาม IP, ระบบสำรองตามรอบ และทดสอบขั้นตอนจริงกับร้าน ยังไม่รวม payment gateway, บัญชีเต็มรูป, loyalty, หลายสาขา, เครื่องพิมพ์เฉพาะทาง หรือการคืนเงินหลังปิดบิล

## หน้าลูกค้าและ QR สั่งอาหาร

- `/menu` ดูเมนู ค้นหา กรองหมวด และราคา ใช้ได้โดยไม่ต้องมีบัญชี
- `/cart` ตะกร้า เพิ่ม/ลดจำนวน หมายเหตุ และยอดประมาณการรวมค่าบริการ/ภาษีก่อนยืนยัน
- `/my-orders` ติดตามสถานะ รับออเดอร์ → จัดเตรียม → เสิร์ฟ พร้อมเรียกพนักงาน/ขอเช็กบิล
- `/booking` จองด้วยชื่อ เบอร์โทร วันเวลา และจำนวนคน รับรหัสจองและยกเลิกได้จากเบราว์เซอร์เดิม
- ฝั่งพนักงาน: `/customer-queue` จัดการออเดอร์และคำขอบริการ, `/qr` แสดง/พิมพ์ QR ตามบิลที่เปิดอยู่

การสั่งอาหารทำได้เมื่อสแกน QR บิลที่กำลังเปิดเท่านั้น QR เป็นลิงก์ลับของบิลนั้น ปิดบิลแล้วสั่งต่อไม่ได้ และเปิดบิลใหม่ต้องใช้ QR ใหม่ อย่านำ QR บิลที่ใช้งานอยู่ไปเผยแพร่สาธารณะ

ออเดอร์ลูกค้าเข้าบิลและตัดสต็อกทันที ป้องกันการส่งซ้ำและการสั่งเกินสต็อก ถ้าราคา/ค่าบริการเปลี่ยนก่อนยืนยัน ลูกค้าจะต้องตรวจยอดใหม่ ยกเลิกจากหน้าคิวออเดอร์จะคืนสต็อกให้ รายการที่เสิร์ฟแล้วไม่สามารถยกเลิกจากคิวได้ ต้องให้ผู้จัดการดูแล บิลจะชำระได้เมื่อไม่มีรายการรอเสิร์ฟ

จองล่วงหน้า 15 นาทีถึง 90 วัน ระบบเลือกโต๊ะที่จุคนพอและว่าง 2 ชั่วโมงต่อการจอง ลูกค้าหนึ่งเบราว์เซอร์มีการจองที่ยังใช้งานได้สูงสุด 3 รายการ เก็บ session ลูกค้าใน SQLite 90 วันเพื่อให้กลับมาติดตามได้หลังรีสตาร์ท ถ้าลบ cookie/เปลี่ยนเบราว์เซอร์จะไม่เห็นประวัติเดิม แต่แจ้งรหัสจองกับพนักงานได้ ไม่มีการส่ง SMS/อีเมลอัตโนมัติ

## ใช้มือถือในร้าน

1. หยุดเซิร์ฟเวอร์เดิมก่อน แล้วเปิด `START-LAN.bat` เพื่อรับการเชื่อมต่อจากเครือข่ายเดียวกัน
2. เชื่อมมือถือกับ Wi-Fi เดียวกับเครื่องร้าน
3. ผู้จัดการไปหน้า QR สำหรับลูกค้า ตั้ง URL เป็น IP ของเครื่องร้าน เช่น `http://192.168.1.20:8765` อย่าใช้ 127.0.0.1 สำหรับมือถือ
4. เปิดโต๊ะจากหลังร้าน แล้วกลับหน้าจัดการ QR เพื่อพิมพ์หรือดาวน์โหลด QR ปัจจุบัน
5. ลูกค้าสแกน เลือกเมนู ยืนยัน แล้วพนักงานจัดการผ่านคิวออเดอร์ลูกค้า

หาก IP เปลี่ยน ต้องอัปเดต URL และพิมพ์ QR ใหม่ เครื่องร้านต้องเปิดโปรแกรมอยู่ตลอด หาก Windows ถามสิทธิ์เครือข่าย ให้เลือกเฉพาะเครือข่ายส่วนตัวที่ร้านเชื่อถือ ไม่ต้องปิด firewall หรือ forward port เราไม่ได้เปลี่ยนกฎ firewall ให้อัตโนมัติ Wi-Fi ที่แยกอุปกรณ์ลูกค้าออกจากกันอาจต้องปรับโดยผู้ดูแลเครือข่าย

ระบบยังเป็นเว็บบนเครื่องร้าน การจองจากนอก Wi-Fi ร้านต้องติดตั้งบนเซิร์ฟเวอร์ที่เข้าถึงจากอินเทอร์เน็ตพร้อม HTTPS ก่อน ไม่ใช่แค่แชร์ลิงก์ 127.0.0.1 หรือ IP ภายใน

## ไลบรารี QR

แนบ qrcode 8.2 ภายใต้ BSD License อยู่ใน `vendor/qrcode-8.2.dist-info/LICENSE` เอกสารต้นทาง: https://pypi.org/project/qrcode/ สร้าง SVG ภายในเครื่อง ไม่ใช้บริการสร้าง QR ภายนอก หากนำ vendor/ ออก สามารถติดตั้งใหม่ด้วย `python -m pip install --target vendor -r requirements.txt`

## โลโก้และเมนูภาพ JUPITER

โลโก้ดาวพฤหัสกับวงโคจร: `assets/jupiter-logo.svg` และสัญลักษณ์ `assets/jupiter-mark.svg` รูปเมนู AI 12 ภาพอยู่ใน `assets/*.webp` ต้นฉบับ PNG อยู่ใน `assets/originals/` แนวภาพและคำสั่งสร้างแต่ละภาพบันทึกใน `assets/image-prompts.json` สร้างด้วย built-in image_gen ไม่มีบริการรูปภายนอกในการใช้งานเว็บ

เพิ่มเมนูตัวอย่าง 8 รายการ: ข้าวกะเพราหมูสับไข่ดาว 79 บาท, ข้าวผัดไก่ 79 บาท, ข้าวไก่กระเทียม 79 บาท, ข้าวไข่เจียวหมูสับ 69 บาท, ชาไทยเย็น 55 บาท, ลาเต้เย็น 65 บาท, มะนาวโซดา 49 บาท และโคล่าใส่น้ำแข็ง 35 บาท แต่ละรายการตั้งสต็อกตัวอย่าง 20 หน่วยและขั้นต่ำ 5 หน่วย ควรปรับราคา ต้นทุน และสต็อกตามร้านจริงก่อนรับขาย

หน้าผู้จัดการ → เมนูและสต็อก → รูปภาพและคำอธิบายหน้าเมนูลูกค้า ใช้เปลี่ยนรูปจากชุดที่มี แก้คำบรรยาย และเลือกป้ายเมนูแนะนำได้ เมนูใหม่ที่ไม่มีรูปจะใช้ภาพเวกเตอร์ตามหมวด รูป AI เป็นภาพประกอบ ไม่ใช่ภาพถ่ายอาหารจริงของร้าน

เพิ่มตาราง `product_presentation` เพื่อแยกรูป/คำบรรยายจากข้อมูลราคาและสต็อก บิลเดิมและราคาสินค้าเดิมไม่เปลี่ยน การติดตั้งภาพครั้งนี้สำรองฐานข้อมูลก่อนเพิ่มเมนูไว้ใน `data/before-menu-styling-*.sqlite3`

## เข้าสู่ระบบและกู้คืนรหัสผ่าน

หน้าเข้าสู่ระบบใหม่ใช้ภาพบาร์ที่สร้างด้วย built-in image_gen อยู่ที่ `assets/login-bar.webp` (ต้นฉบับ `assets/originals/login-bar.png`) คำสั่งสร้างอยู่ใน `assets/login-image-prompt.json` รองรับแสดง/ซ่อนรหัสผ่าน เตือน Caps Lock เติมชื่อผู้ใช้เดิมเมื่อรหัสผิด และป้องกันส่งแบบฟอร์มซ้ำระหว่างเข้าสู่ระบบ การช่วยแสดงรหัสผ่านใช้ JavaScript เล็กน้อยที่ฝังในหน้า Python

“ลืมรหัสผ่าน” ให้พนักงานติดต่อผู้จัดการเพื่อยืนยันตัวตน ผู้จัดการเข้าเมนู “กู้คืนบัญชี” เลือกบัญชีและยืนยันรหัสผ่านของตนเอง แล้วรับลิงก์ใช้ครั้งเดียว หมดอายุ 15 นาที ลิงก์ใหม่ยกเลิกลิงก์เก่าของบัญชีนั้น เก็บเฉพาะ hash ของ token ในฐานข้อมูล ไม่ส่งอีเมล/SMS และไม่บันทึกรหัสผ่านใน audit

เมื่อตั้งรหัสผ่านใหม่ต้องกรอกสองครั้งให้ตรงกัน อย่างน้อย 10 ตัว และระบบจะออกจากอุปกรณ์ที่เคยเข้าสู่ระบบของบัญชีนั้น ผู้จัดการยกเลิกลิงก์ที่ยังไม่ได้ใช้ได้จากหน้ากู้คืนบัญชี

หากลืมบัญชีผู้จัดการเพียงคนเดียว ผู้ดูแลเครื่องร้านที่ได้รับอนุญาตเปิด `RECOVER-ACCOUNT.bat` และกรอกชื่อผู้จัดการเพื่อรับลิงก์กู้คืนบนเครื่องนั้น เครื่องมือใช้สิทธิ์เข้าถึงไฟล์ฐานข้อมูลในเครื่อง จึงต้องจำกัดสิทธิ์เข้าถึงคอมและโฟลเดอร์ข้อมูล ไม่ควรแชร์เครื่องมือนี้หรือไฟล์ฐานข้อมูลให้บุคคลอื่น

ลองเข้าสู่ระบบผิด 8 ครั้งในช่วง 10 นาทีต่อชื่อผู้ใช้หรือ IP จะต้องรอให้พ้นช่วงเวลาดังกล่าวก่อนลองอีกครั้ง

ปุ่ม “ทดลองสั่ง” ใช้ลิงก์ภายในเว็บที่เปิดอยู่ จึงไม่ขึ้นกับ IP สำหรับมือถือ ส่วน QR ยังคงใช้ URL ของร้านที่ตั้งไว้ ต้องอัปเดตเมื่อเครือข่ายเปลี่ยน

## ระบบกะ คิวสด และแบ่งชำระ

ดูขั้นตอนใช้งานใน [คู่มือกะและแบ่งชำระ](คู่มือกะและแบ่งชำระ.md) ต้องเปิดกะก่อนรับเงิน หน้า `/shifts` จัดการกะ, `/checkout?id=หมายเลขบิล` ชำระ/แยกบิล, `/part-receipt?id=หมายเลขบิลย่อย` แสดงใบรับเงินส่วนแบ่ง และ `/customer-queue` มีคิวสดพร้อมปุ่มเปิดเสียง หน้าออเดอร์ลูกค้าอัปเดตอัตโนมัติด้วย

เพิ่มตาราง shifts, cash_events, checkout_totals, bill_parts และ payments พร้อมช่องทางจ่าย/กะ/รหัสกันคำขอซ้ำใน expenses ข้อมูลยอดเงินยังเก็บเป็นสตางค์ การชำระหลายครั้งใช้ธุรกรรม SQLite เพื่อป้องกันยอดเกินและการรับเงินซ้ำ

ตัวเลือกแยกบิลรองรับหารตามจำนวนคนหรือกำหนดยอดเอง ไม่ใช่แยกตามรายการอาหาร ยังไม่มีคืนเงินหลังรับชำระหรือย้าย/รวมโต๊ะ

## ผังเลือกโต๊ะสำหรับการจอง

หน้า `/booking` เลือกวัน เวลา และจำนวนคนก่อน แล้วเลือกโต๊ะ T01–T12 จากผังหรือรายการ สำรองโต๊ะเป็นช่วง 2 ชั่วโมง ผังเป็นแบบจำลอง มีเวที บาร์ ทางเข้า และห้องน้ำ โซนและตำแหน่งปรับได้ที่ `floor_plan.py` ในตัวแปร `LAYOUT` ควรปรับให้ตรงร้านจริงก่อนนำไปใช้กับลูกค้า โต๊ะ DEMO ไม่เปิดให้จองจากผัง

สถานะโต๊ะอิงเวลาที่ค้นหา: ว่าง, มีการจองแล้ว, กำลังใช้งาน (กรณีจองใกล้เวลาปัจจุบัน), ที่นั่งไม่พอ ระบบตรวจซ้ำในธุรกรรมตอนยืนยัน ไม่พักโต๊ะไว้ระหว่างกรอกข้อมูล ป้องกันจองชนกันและส่งฟอร์มเดิมซ้ำ มีรหัสจองให้แจ้งพนักงาน การจองจากผังเข้าหน้าการจองหลังร้านเดิม

การรับจองยังไม่ผูกเวลาเปิดร้านหรือเงินมัดจำ และการเปิดบิลหน้าร้านยังต้องให้พนักงานตรวจการจองก่อนเปิดโต๊ะ

## เพิ่มเมนูและอัปโหลดรูป

ผู้จัดการเข้าเมนูและสต็อก แล้วใช้ส่วนเพิ่มเมนูพร้อมรูปภาพ ใส่ชื่อ หมวด ราคา ต้นทุน สต็อก คำอธิบายและป้ายแนะนำ เลือกรูปเพื่อดูตัวอย่างก่อนบันทึก รองรับภาพนิ่ง JPG, PNG, WebP ไม่เกิน 5 MB และ 20 ล้านพิกเซล ระบบปรับแนวตาม EXIF ย่อสูงสุด 960 พิกเซล และบันทึก WebP โดยใช้ชื่อสุ่มใน assets/menu-upload-*.webp ต้องติดตั้ง Pillow ตาม requirements.txt

เปลี่ยนรูปในส่วนรูปภาพและคำอธิบายหน้าเมนูลูกค้า เลือกสินค้า ระบบโหลดข้อมูลเดิมให้ เลือกรูปใหม่แล้วบันทึก หรือเลือกใช้ภาพประกอบตามหมวดและล้างรูปใหม่ที่เลือกเพื่อเอารูปออกจากเมนู ภาพเดิมเก็บไว้เพื่อไม่กระทบเมนูอื่นที่ใช้งานร่วมกัน รูปจริงที่อัปโหลดแสดงบนหน้าลูกค้าได้ทันที สำรองโฟลเดอร์ assets พร้อมฐานข้อมูลเมื่อต้องการย้ายเครื่อง

## ค้นหา กรอง และข้อมูลที่กรอกค้าง

หลังร้านมีค้นหาและกรองเมนูตามหมวด/สต็อก โต๊ะตามสถานะ และการจองตามชื่อ เบอร์ โต๊ะ รหัสหรือสถานะ ตัวกรองทำงานบนรายการที่โหลดอยู่ ไม่เปลี่ยนข้อมูลฐานข้อมูล การปรับสต็อกยังรวมแถวที่กรอกไว้แม้ซ่อนด้วยตัวกรอง

แบบฟอร์มสต็อก เพิ่ม/แก้เมนู การจองพนักงาน และรายจ่ายเก็บข้อความที่กรอกเมื่อบันทึกไม่สำเร็จในเซสชันของผู้ใช้ หลังบันทึกสำเร็จจะล้างข้อมูลนั้น ออกจากระบบหรือรีสตาร์ตโปรแกรมแล้วข้อมูลที่ยังไม่บันทึกนี้จะไม่อยู่ รูปที่เลือกต้องเลือกใหม่ตามข้อจำกัดของเบราว์เซอร์

การ์ดโต๊ะมีปุ่มรายการ QR เฉพาะโต๊ะและรับชำระ หากมีการจองใกล้เวลาเปิดภายใน 2 ชั่วโมง จะเตือนและต้องติ๊กยืนยันว่าตรวจการจองแล้ว การเปิดโต๊ะไม่ได้เปลี่ยนการจองเป็นมาแล้วให้อัตโนมัติ ต้องให้พนักงานจัดการสถานะจองเอง คิวออเดอร์แสดงเวลารอและเตือนตั้งแต่ 15 นาที

ผู้จัดการปรับสต็อกหลายเมนูได้ในหน้าเมนูและสต็อก: กรอกจำนวนเพิ่ม/ลดในแต่ละแถว โดยค่าเริ่มต้นเป็น 0 ใส่เหตุผลรวม หรือเหตุผลเฉพาะแถว แล้วกดบันทึกการปรับสต็อกทั้งหมด ยอดหลังปรับบนหน้าจอเป็นตัวอย่าง ระบบใช้สต็อกล่าสุดตรวจและบันทึกในธุรกรรมเดียว ถ้ารายการใดลดเกินสต็อกจะยังไม่บันทึกทั้งชุด ป้องกันส่งแบบฟอร์มเดิมซ้ำและเก็บประวัติ movements แยกแต่ละรายการ ปุ่มปรับรายการนี้ใช้เฉพาะแถวนั้น

## ตะกร้าแบบการ์ดและคิวสามขั้นตอน

ตะกร้าแสดงรูป ราคา จำนวนและยอดต่อรายการเป็นการ์ด เพิ่ม/ลดจำนวนแล้วระบบบันทึกผ่านเบราว์เซอร์โดยไม่โหลดหน้าใหม่ พร้อมอัปเดตยอดและรหัสตรวจราคา ปุ่มยืนยันจะรอจนบันทึกจำนวนเสร็จและไม่มีข้อผิดพลาด ปุ่มบันทึกจำนวนยังใช้ได้เมื่อปิด JavaScript

หน้าผู้จัดการแบ่งเป็นรายการเมนู ปรับสต็อก เพิ่มเมนู และแก้ไขเมนู สลับแท็บในหน้าเดียวได้โดยข้อมูลที่กรอกยังอยู่ ข้อมูลที่ยังไม่บันทึกไม่ได้รับประกันว่าจะอยู่หลังปิดแท็บหรือออกจากหน้า

คิวแยกรอรับออเดอร์ → กำลังจัดเตรียม → พร้อมเสิร์ฟ (ready) และปุ่มเสิร์ฟแล้ว ขั้น ready ยังถือเป็นออเดอร์ค้าง ต้องเสิร์ฟก่อนยืนยันยอดรับชำระ ประวัติเสิร์ฟ/ยกเลิกแสดงในส่วนพับได้ และติดตามสถานะจากหน้าลูกค้าได้เหมือนเดิม

คำขอเช็กบิลใช้ปุ่มไปชำระเงินเพื่อเปิดหน้าชำระของโต๊ะนั้น และเปลี่ยนคำขอเป็น handling (กำลังเช็กบิล/รอชำระ) โดยไม่รับเงินหรือปิดบิล คำขอยังอยู่ในคิวพร้อมปุ่มชำระต่อจนรับเงินครบ จึงเปลี่ยนเป็น done อัตโนมัติ คำขอเรียกพนักงานใช้ปุ่มดูแลแล้วและอยู่หน้าคิวต่อ ถ้ามีออเดอร์รอเสิร์ฟ หน้าชำระจะแสดงคำเตือนและทางกลับคิว และระบบไม่ให้ยืนยันยอดก่อนเสิร์ฟครบ

# จัดการโต๊ะและการยกเลิกรายการ

หน้าโต๊ะและออเดอร์มีแผนผังให้แตะเลือกโต๊ะ และระบุจำนวนลูกค้าตอนเปิดโต๊ะ ภายในบิลมีส่วนจัดการโต๊ะสำหรับย้าย เพิ่มโต๊ะร่วม (บิลเดียวหรือแยกบิล) คืนโต๊ะร่วม และปรับจำนวนคน ผู้จัดการรวมบิลและยกเลิกอาหารได้ โดยต้องระบุเหตุผลและตรวจข้อมูลก่อนยืนยัน ระบบตรวจความจุ การจองใกล้เวลา บิลที่เริ่มชำระ และข้อมูลที่เปลี่ยนโดยพนักงานคนอื่นอีกครั้งในธุรกรรมเดียว

เมื่อชำระหรือยกเลิกบิลที่มีรายการ โต๊ะจะรอทำความสะอาด พนักงานกดพร้อมใช้งานก่อนเปิดใหม่ การยกเลิกเปิดโต๊ะที่ยังไม่มีรายการคืนเป็นว่างทันที ออเดอร์ลูกค้าที่ยังไม่เริ่มทำคืนสต็อกได้ แต่รายการที่เริ่มทำหรือเสิร์ฟแล้วบันทึกของเสีย รายการเพิ่มโดยพนักงานให้ผู้จัดการเลือกตามจริง ต้นทุนของเสียแสดงและหักในกำไรประมาณการของรายงานตามวันที่ยกเลิก

เมื่อย้ายหรือรวมบิล ลูกค้าที่เปิดหน้าสั่งไว้แล้วใช้งานต่อได้ แต่ QR เก่ารับการสแกนใหม่ไม่ได้ ต้องแสดง QR ใหม่จากหน้าบิล มีประวัติผู้ดำเนินการและเหตุผล บิลที่รับเงินแล้วไม่สามารถย้ายหรือรวมได้ กลุ่มที่แยกบิลให้แยกออกจากกลุ่มก่อนย้าย ส่วนกลุ่มบิลเดียวสามารถย้ายทั้งหมดไปโต๊ะใหม่ที่มีความจุเพียงพอได้

# ตัวเลือกเมนูและหน้าทำงานตามหน้าที่

ผู้จัดการเปิดเมนู “ตัวเลือกเมนู” เพื่อเพิ่มกลุ่มตัวเลือก ตั้งราคา/ต้นทุนเพิ่ม เปิดหรือปิดตัวเลือก และกำหนดให้แต่ละเมนูส่งเข้าครัวหรือบาร์ ลูกค้าเลือกเมนูเดียวกันหลายแบบในตะกร้าได้ เช่น ข้าวผัดธรรมดากับข้าวผัดเพิ่มไข่ ระบบแสดงราคาต่อรายการที่รวมตัวเลือก ตรวจสต็อกรวมของเมนูหลักทุกแบบ และเก็บชื่อ ราคา ต้นทุนที่สั่งเป็นประวัติ การปรับตัวเลือกภายหลังไม่แก้บิลเก่า สต็อกยังนับเป็นจำนวนจาน/แก้วของเมนูหลัก ไม่ใช่คลังวัตถุดิบแยกรายชนิด

หน้า “คิวครัว / บาร์ / เสิร์ฟ” อัปเดตทุก 5 วินาที เปิดเสียงแจ้งเตือนได้ และเตือนเมื่อรอเกิน 15 นาที อัปเดตทีละรายการตามขั้นตอน รอจัดเตรียม → กำลังทำ → พร้อมเสิร์ฟ → เสิร์ฟแล้ว บิลรับชำระได้เมื่อเสิร์ฟครบ รายการเพิ่มใหม่ผ่านหน้าบิลเข้าคิวด้วย รายการเดิมที่เพิ่มโดยพนักงานก่อนใช้ระบบนี้เก็บสถานะเดิมไว้โดยถือว่าเสิร์ฟแล้ว

ผู้จัดการกำหนดหน้าที่บัญชีพนักงานใน “ตั้งค่าและพนักงาน” ได้เป็น พนักงานทั่วไป / บริการหน้าร้าน / ครัว / บาร์ / แคชเชียร์ บัญชีเดิมยังเป็นพนักงานทั่วไปจนกว่าจะเปลี่ยนหน้าที่ ครัวและบาร์เห็นเฉพาะคิวของตนเอง และส่งรายการถึงพร้อมเสิร์ฟ หน้าร้านยืนยันเสิร์ฟ แคชเชียร์ดูแลรับเงินและกะ ผู้จัดการเข้าถึงทุกงาน ระบบตรวจสิทธิ์บนเซิร์ฟเวอร์ด้วย ไม่ได้เพียงซ่อนปุ่มในหน้าเว็บ

# หน้าทำงานที่รวบไว้

คิวลูกค้าและคิวครัว/บาร์รวมเป็น “ออเดอร์และบริการ” มีงานทั้งหมด งานบริการ/เช็กบิล และประวัติ สถานะทั้งออเดอร์สรุปจากรายการอาหารแต่ละรายการ ลิงก์คิวเดิมยังพาไปหน้ารวมใหม่ได้ ครัวและบาร์เห็นเฉพาะงานของตนเอง

หน้า “จัดการเมนู” เลือกสินค้าเดียวแล้วแก้ข้อมูล ราคา ต้นทุน รูปภาพ และแผนกในฟอร์มเดียว บันทึกเป็นธุรกรรมเดียว หากรูปไม่ถูกต้องข้อมูลทั้งชุดจะไม่เปลี่ยน ตัวเลือกของสินค้านั้นอยู่ด้านล่าง โดยมีปุ่มบันทึกของแต่ละตัวเลือก สต็อกหลายรายการยังมีแท็บแยกเหมือนเดิม

ปุ่มแสดง QR ของบิลเปิดเป็นหน้าต่างในหน้าเดิม มีลิงก์บันทึกและเปิดหน้าพิมพ์ ส่วนหน้ารวม QR ยังใช้พิมพ์หลายโต๊ะได้ คำสั่งโต๊ะรวบใต้ “จัดการโต๊ะ” ตะกร้าบันทึกจำนวนอัตโนมัติ โดยปุ่มลองบันทึกจะแสดงเมื่อเกิดปัญหา ถ้าปิด JavaScript ปุ่มบันทึกเดิมยังใช้งานได้ ใบเสร็จมีปุ่มพิมพ์และกลับหน้าโต๊ะ
